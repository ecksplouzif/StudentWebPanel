# Студенческая панель — план работ

Роль: ты — исполнитель, я — постановщик. Здесь только ЧТО делать и в каком порядке. КАК — твоя работа; где решение неочевидно, приноси два варианта с плюсами/минусами, обсудим. Стек зафиксирован ранее и не пересматривается: Go, HTMX, Supabase (Postgres + Auth), Nginx, VPS.

## Правила работы

- Один вертикальный срез за раз. Фаза считается закрытой только когда её Definition of Done выполнен **на проде**, не локально.
- Внутри фазы новые фичи не добавляются. Все идеи «раз уж полез» — строчкой в `BACKLOG.md`.
- Застрял дольше чем на ~2 часа — формулируешь проблему письменно (что делал, что ожидал, что получил) и приносишь. Не долби стену молча.
- Каждая рабочая сессия заканчивается коммитом с внятным сообщением.
- Принятые по ходу решения — по 2–3 строки в `docs/decisions.md`: что решил и почему. На собеседованиях это золото.
- «Вечер» ниже ≈ 2–3 часа. Оценки грубые; пиши рядом факт — заодно научишься оценивать себя.

---

## Фаза 0 — Каркас проекта (1–2 вечера)

- [+] Репозиторий на GitHub, `.gitignore`, лицензия
- [+] README-заглушка: один абзац — что за продукт и для кого; место под ссылку на прод
- [+] Каркас HTTP-сервера с эндпоинтом здоровья
- [+] Конфигурация через переменные окружения, в репо — `.env.example`
- [+] Линтер и форматтер
- [+] Makefile (или аналог): run / build / lint
- [ ] Структура каталогов проекта выбрана и описана в README
- [ ] Логирование входящих запросов

**DoD:** свежий клон репозитория поднимается по README за две команды, эндпоинт здоровья отвечает.

## Фаза 1 — Авторизация (2–4 вечера)

- [ ] Проект в Supabase, включён вход через Google
- [ ] Страница входа
- [ ] Обработка возврата после логина, установка сессии
- [ ] Все защищённые маршруты требуют входа, аноним уходит на страницу логина
- [ ] Текущий юзер доступен обработчикам запросов
- [ ] Профиль юзера создаётся/обновляется в БД при первом входе
- [ ] Защищённая страница, показывающая имя вошедшего
- [ ] Выход из аккаунта

**DoD:** одногруппник (не ты) входит со своего Google-аккаунта и видит своё имя.

## Фаза 2 — Прод с первого дня (2–3 вечера)

- [ ] VPS: вход только по ключу, пароли выключены, firewall пропускает минимум портов
- [ ] Отдельный непривилегированный юзер под приложение
- [ ] Домен, DNS указывает на сервер
- [ ] Nginx как reverse proxy, HTTPS с автопродлением сертификата
- [ ] Приложение как сервис: стартует при загрузке, перезапускается при падении
- [ ] Секреты живут на сервере, в репозиторий не попадают
- [ ] Деплой одной командой с твоей машины
- [ ] Процедура деплоя и восстановления описана в README
- [ ] Прод-адрес добавлен в разрешённые адреса авторизации в Supabase

**DoD:** логин работает по https-домену с телефона; выкат новой версии = одна команда.

## Фаза 3 — Расписание, только чтение (3–4 вечера)

- [ ] Спроектировать хранение расписания (пары, предметы, время, тип занятия); решение коротко зафиксировать в `docs/`
- [ ] Механизм миграций БД + первая миграция
- [ ] Руками занести 2–3 реальных учебных дня
- [ ] Страница «Сегодня»: пары по порядку с временем
- [ ] Вид «Неделя»
- [ ] Подсветка текущей и следующей пары
- [ ] Пустые состояния: выходной, нет данных
- [ ] Проверить вёрстку на телефоне

**DoD:** реальное расписание твоей группы на неделю открывается на проде и им можно пользоваться вместо ДЛ.

## Фаза 4 — Импорт расписания из файла универа (3–5 вечеров)

- [ ] Взять свежий экспорт, письменно задокументировать в `docs/` все особенности формата
- [ ] Составить словарь сокращений предметов своей группы
- [ ] Правила разбора закодированного поля темы зафиксировать текстом ДО написания кода
- [ ] Импорт файла в БД (способ запуска — любой удобный, пока только для тебя)
- [ ] Корректная обработка кодировки, переносов строк, дат
- [ ] Нераспознанная строка не роняет импорт, а попадает в отчёт об ошибках
- [ ] Повторный импорт того же файла не создаёт дублей
- [ ] Залить семестр целиком, выборочно сверить 3 дня с ДЛ глазами

**DoD:** семестр импортируется одной командой, повторный запуск безопасен, отчёт об ошибках читаем.

## Фаза 5 — Предметы и ссылки на пары (2 вечера)

- [ ] Справочник предметов: полное название, преподаватель, ссылка на созвон
- [ ] Редактирование справочника (пока доступно только тебе)
- [ ] Ссылка на созвон видна в расписании у каждой пары

**DoD:** с телефона со страницы «Сегодня» в два тапа попадаешь в нужный созвон.

## Фаза 6 — Домашки и дедлайны (3–4 вечера)

- [ ] Хранение заданий: предмет, описание, срок сдачи
- [ ] Список заданий: ближайшие сверху, просроченные выделены
- [ ] Создание, редактирование, удаление задания (пока только тобой)
- [ ] Личная отметка «сделал» — у каждого студента своя, на других не влияет
- [ ] Блок «ближайшие дедлайны» на главной

**DoD:** вся реальная домашка группы на текущую неделю внесена и видна одногруппникам.

## Фаза 7 — Роли и админка старосты (3–4 вечера)

- [ ] Роли: студент и староста
- [ ] Способ выдачи роли (пока руками — допустимо, но процедура описана в `docs/`)
- [ ] Редактирование заданий, справочника и запуск импорта доступны только старосте
- [ ] Проверить с аккаунта студента, что мутации недоступны, включая прямые URL
- [ ] Раздел администрирования, где всё редактируемое собрано в одном месте

**DoD:** Фёдор со своего аккаунта добавляет домашнее задание без твоего участия.

## Фаза 8 — Объявления (2 вечера)

- [ ] Лента объявлений
- [ ] Создание, редактирование, удаление — только староста
- [ ] Свежие объявления видны с главной

**DoD:** объявление старосты одногруппник видит с телефона без подсказок, где искать.

## Фаза 9 — Пилот на группе (1–2 недели фоном)

- [ ] Инструкция входа длиной в одно сообщение для чата группы
- [ ] Позвать 3–5 одногруппников
- [ ] Канал обратной связи + `BACKLOG.md` для жалоб и идей
- [ ] Простейший учёт активности: кто и когда заходил
- [ ] Еженедельный разбор: чинить топ-3 проблемы, остальное в бэклог

**DoD:** минимум 5 человек за неделю зашли сами и повторно; главные жалобы закрыты или осознанно отложены.

## Фаза 10 — Полировка под резюме (2–3 вечера)

- [ ] Пройтись по всем формам: валидация, внятные сообщения об ошибках
- [ ] Страницы 404/500 не выглядят голым текстом
- [ ] Проверить восстановление БД из бэкапа на деле, а не «наверное работает»
- [ ] README: скриншоты, схема архитектуры одной картинкой, абзац «чем проект интересен технически»
- [ ] Пункт в CV: ссылка на прод и репозиторий + 2–3 строки с цифрами (пользователи, объём данных, аптайм)

**DoD:** незнакомый разработчик за две минуты по README понимает, что это, как устроено и что ты умеешь.

---

**Итого:** ~25–30 вечеров чистой работы. При трёх вечерах в неделю — 2–3 месяца с пилотом. Если где-то идёшь сильно быстрее оценки — хорошо; сильно медленнее — приходи разбирать, что тормозит, а не молчи.
